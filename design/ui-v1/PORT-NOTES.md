# Porting airglow UI v1.2 into `app/` and `android/`

For the engineer porting `design/ui-v1/` into the Capacitor app. Read `UI-SPEC.md` for what each screen does; this file is about **what to copy, what to throw away, and what is faked**. All sizes are CSS px on a 960 x 540 canvas (the Philips WebView, 2x); native sizes are dp, the same numbers.

## 2. Class naming

- No prefix for app components (they are the app's own): `.topbar .tab`, `.btn .btn2`, `.chip`, `.pillbtn`, `.tag`, `.pc` (poster), `.hc` (home rail card), `.wc` (16:9 card), `.gc` (game card), `.lr` (menu row), `.sheet`, `.menu`, `.toast`, `.notice`, `.state`.
- Group prefixes: `.g-*` guide, `.lib-*` library, `.d-*` detail, `.gd-*` game detail, `.nv-*` **native-player overlays drawn in HTML only for the mock** (do not ship these; they exist to measure the Java views), `.mt/.side/.sc` the broadcast-graphic matchup, `.slab*` the hero slab.
- State classes `f`, `f-ring`, `f-in`, `lift`, `sel`, `on`, `dis`, `cur` are **mock focus/selection markers**. In the app: `sel`/`on`/`dis` stay as real classes (selected is not focused); the focus ones become pseudo-classes.
- Launch: everything is `.l-` / `#l-`. Do not rename.
- Tokens only: no hex in components (the team palette in `data.js` and the crest colours are the only intended hex values).

## 4. Port order (each step ships and is testable on the TV)

1. **Tokens, fonts, top bar, focus model.** Add `tokens.css` + `fonts.css`, port `topbar`, the `:focus` ring rules, Back = scroll-top-then-tab in `nav.js`. Gate everything behind `data-scale="tv"` so desktop is untouched. Drop in `tools/audit.js` against the live app.
2. **Poster grid + Movies/Series screen** (`.lib-*`, `.pc`). It is the heaviest list: build the virtualised grid first (`data-nav="grid"` in `nav.js` already limits measurement to 49 cards; keep it). Measure frame time with key repeat before anything else is built on top.
3. **Detail pages** (movie, series, version sheet) with the full-bleed backdrop and flowing column.
4. **Home** with the resume hero and the `.hc` rails (no game yet), then the hero for the game variants, using `nba.js` data.
5. **Live guide** (`.g-*`, 6 rows, virtualised) and the group sheet; favourites ring.
6. **NBA hub + game page** and the **spoiler shield** (section 5) as one piece of work, including the guide and Home surfaces.
7. **Search, Saved, Account, update card, states** (cheap, mostly forms).
8. **Native player overlays** (`PlayerActivity.java`): banner, hint bar, channel panel, groups, options, subtitles/audio/picture, VOD controls first; then game panel, Live games, chip, score bug, failure card, Sync.
9. **Launch** (`launch/`) once the app can say "home is ready"; native splash resources last.
10. **First-run sign-in** with the phone path (section 5 has what it needs).
11. **Opt-in previews** only after the TV test (section 5).

## 5. What is fake and needs real data or logic

- **Spoiler shield (biggest).** `nba.js` already fetches ESPN scoreboard/summary. Needed: a single `Shield` module (`off | my team | all`, persisted in `Core.store`) that every render path passes scores through, and the **synced-delay clock**: store a delay per channel (`delay[channelId]`, default 60 s), keep a ring buffer of feed snapshots, and render the snapshot at `now - delay`. Anything derived from scores must obey it too (leaders, records, "OT", winner emphasis, per-quarter lines, a points column, guide descriptions, notifications). Reveal state is per game per session. The game panel is the reveal for the game on the current channel; a hidden panel never contains points. Sync = pick the game-clock value shown on the broadcast; delay = `now - feed time at which the clock read that value`, so the feed must expose per-event clock values (verify ESPN's play-by-play granularity; spec section 13.8). Under the shield also suppress previews of that game's channel.
- **Team to channel link.** Mocks hard-code "Grizzlies at Warriors on NBA League Pass 4". Real: match ESPN game to guide programme by team names (`nba.js` `nameRe`/`cityRe` are the start), rank candidate channels (guide match, League/NBA group, Sports group), store the pick per team. **Feeds**: every channel whose current programme matches the game is a feed (2 of 3); the failure card and Options list them, best first.
- **Version merging and titles.** One card per title with "+N versions": group provider items by `Titles.clean(name).key + year` (`app/titles.js` exists), then pick the default version (user's language, best quality this TV decodes via `MediaCodecList`), remember the choice per title. The mocks' `vers`, sizes ("18.4 GB") and subtitle lists are invented; size needs `Content-Length` or provider info, which many do not send (hide the size when unknown).
- **Posters, backdrops, programme frames.** All procedural in the mocks. Real: provider art plus TMDB (provider TMDB id) for backdrops; fall back to the initials tile. **Image pipeline is native**: `shouldInterceptRequest` to Coil or Glide, downscale to the slot (248 x 372 posters), disk cache. Without it a grid scroll decodes full-size JPEGs.
- **Ratings, "Popular" sort, rank bands, counts in Filters.** Mocked numbers. Real: IMDb ratings file (`scripts/build-ratings.js`), a weekly popularity source, and count queries over the local index per chip (cache them; zero-count chips are disabled, not hidden).
- **Live previews (hero, guide).** Mocked as a still. Real: a **second `PlayerView`/ExoPlayer in `MainActivity`** layered *behind* a transparent WebView region (today playback is a separate `PlayerActivity`, so this is new plumbing), muted, 1.5 s dwell, one reused connection handed to the full player on OK, off when the account has `max_connections` = 1, off by default, never for a shielded game's channel. The preview is a rectangle; the slant is two static shapes in the WebView on top. Test the Philips for a second decode surface before enabling anywhere.
- **Guide data.** The mock grid is hand-written. Real: XMLTV/short EPG per channel, cached; "now" = 10-minute floor; missing guide = dashed cell, still tunable.
- **Channel logos.** `iniOf` tiles stand in for provider logos; load `stream_icon` and fall back to the tile.
- **Resume/Continue watching, Saved order, History.** Persist positions locally (`Core.store`); a finished episode becomes the next one.
- **Hero choice.** Computed from the cached schedule (tip-off times known days ahead) before first paint and locked for 3 s; not from live data.
- **Offline/cached Home.** Needs a serialised last-good Home model (hero, rails, guide window) written after each successful load; the offline bar and the 12 s launch path read it.
- **Update card.** `TunerPlayerPlugin.installUpdate` exists; the card needs the "is an update ready, downloaded" state and a quiet-moment check (never in the player or a game window).
- **Voice search.** The mic key launches `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` from the plugin and returns text to the WebView; handle `KEYCODE_SEARCH` in `MainActivity`. Needs a recogniser on the box: Google TV usually has the Google app, cheaper Android TV builds may not. Detect with `PackageManager.queryIntentActivities` and hide the mic key if absent. The Google TV remote's mic button goes to Assistant by default; only the app's own mic key (or KEYCODE_SEARCH on remotes that send it) reaches the app. Not verified on the Philips.
- **QR / phone sign-in: no relay server needed on the home network, and a relay is a bad idea.** What it needs: the TV runs a tiny HTTP server on a random port (a Capacitor plugin around `NanoHTTPD` or `java.net.ServerSocket`; cleartext is already allowed in the manifest), serving one static form page. The QR encodes `http://<TV LAN IP>:<port>/?t=<one-time token>`; the 4-digit code on screen is a second factor typed on the phone. The phone POSTs `{server, username, password}` (or an M3U URL) to the TV, the TV validates it (same `Core` Xtream check as typing) and the server stops. Needs: the LAN IP (`WifiManager`/`ConnectivityManager`), a real QR generator (the mock draws random squares; use a small JS QR encoder, one `<img>`/canvas), token expiry (5 min), a "Waiting for your phone" state with cancel, and Wi-Fi AP isolation or guest networks will block it (the "Type it here instead" fallback is not optional). A cloud relay would mean provider credentials leave the house; do not add one for this. The mock's IP and code are fake.
- **Subscription/expiry, connections "1 of 2".** From the Xtream `user_info` (`exp_date`, `max_connections`, `active_cons`); the mock text is invented.
- **Zap direction, Account settings.** Real settings in `Core.store`; the player must read them.
- **Fonts.** Brand ships `latin` only. Polish/Turkish/Czech/Hungarian titles fall back mid-word until `latin-ext` files exist (open item for the brand).

## 6. Native player (`PlayerActivity.java`, Media3)

`kit/player.js` is the measured spec, section 7 of the spec is the table. Practical notes:
- The activity already builds its views in code (`FrameLayout` root, `PlayerView`, `TextView osd`, a stats `LinearLayout`). Add the overlays as sibling views, one panel at a time; sizes in dp equal the mock's CSS px, colours are the tokens.
- **Focus inside a panel is an inset 3 dp ring over surface-3 with no scale** (a `GradientDrawable` stroke inside the row); rows never change size. Do not use `clipChildren` on the panel.
- The skewed score plate is a custom `Drawable` with a `Path` skewed 12 degrees, not a rotated `GradientDrawable`.
- The hint bar is 56 dp tall with text at y 489 to 507; panels end at y 480.
- Key map is in spec section 7 (OK = channel panel always; chip and Up next rewrite the hint bar's OK). The shield state and delay come from the WebView through the plugin (`command`), because the data module lives in JS; push the current synced score, clock and shield flag to the activity on change, and send "reveal" and "sync" results back.
- Honour system caption style (`CaptioningManager`, `CaptionStyleCompat`).

## 7. Gotchas that cost time in the mocks

- Chrome 113: no `:has()`-style tricks needed, but `-webkit-line-clamp` boxes report `display:flow-root`; the audit knows.
- Never `mask`, `filter`, or `clip-path` on anything that moves (video, animated cards). `clip-path` on static shapes (slab edge, wedge) is fine.
- Animate only `transform` and `opacity`; no smooth scroll while a key repeats.
- `text-overflow: ellipsis` does nothing on a flex container: put it on an inner block span.
- A focus ring needs 5 px plus the scale growth plus 2 px of air to its neighbours; at the screen edge the scale must grow inward (`transform-origin`). `tools/audit.js` enforces it.
- Team colours are the teams' real colours (owner decision); the safeguards are an 8 px gap to LIVE pills, no contact with rings, 4.5:1 text on plates (`Kit.textOn`), and LIVE never identified by colour alone.
